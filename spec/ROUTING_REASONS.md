# Routing Reasons

**Every on-demand practice's routing choice, side by side.** A practice
shows up in a session through its file pattern (`applies_to`: editing a
file that matches brings it in), through a named moment (`gates`: merge,
review, push, reply), or through the occasion index. Each practice says
why its pattern is what it is in its own `applies_to_why` line, and why
its moment in `gates_why`; this page collects them so the choices can be
read together and one rule applied to all of them.

**The rule they are held to:** a pattern is justified only where the path
identifies what is *distinctive* about the practice's occasion, not merely
something that is always true of it. `**` means no path reaches it, and
the reason says what does instead.

**Where it came from.** Until 2026-09-29 these reasons lived in a second,
hand-kept list, `tools/routing_scope.json`, which drifted from the
practice files and let a new practice arrive without an entry. The reasons
moved into the practices, and this page is rebuilt from them, so it cannot
drift ([spec/PRACTICE_FORMAT.md](PRACTICE_FORMAT.md), "applies_to_why").
